# Скрябины — семейный архив

Живой сайт для семьи: история фамилий, дерево на 75+ человек, наглядная
схема родства, и админка для Марины Алексеевны — добавлять людей,
фотографии, уточнять сведения. **Все правки хранятся на сервере и видны
сразу всем посетителям сайта**, а не только в браузере Марины.

## Что нового по сравнению с первой версией

- **Общее хранилище.** Раньше правки жили в localStorage конкретного
  браузера. Теперь это делает `server.js` — маленький API без внешних
  зависимостей, данные лежат в файле `data/overlay.json` на сервере.
  Любой человек, открывший сайт, видит те же данные (обновление — раз в
  ~20 секунд автоматически, или сразу при переходе между страницами).
- **Новый дизайн** — «созвездие поколений»: тёмный фон, яркие акценты
  по линиям родства (фиолетовый — отец, бирюза — мать, коралл — родня
  мужа), шрифты Fraunces + Manrope.
- **Страница «Схема»** — интерактивная радиальная схема родства:
  расстояние от центра = степень родства, нажатие на точку открывает
  карточку человека. Можно выбрать любого человека центром схемы, не
  только Марину. Работает зум колесом мыши, щипком на телефоне,
  перетаскиванием — плюс кнопки +/−/сброс и мини-карта в углу, так что
  схема удобна и на маленьком экране, не только на десктопе.
- **Страница «Хронология»** — все известные даты рождения и смерти на
  одной горизонтальной шкале времени, от самой ранней известной даты до
  наших дней.
- **Живой звёздный фон** — на каждой странице, с лёгким параллаксом от
  движения курсора; уважает системную настройку «уменьшить анимацию».
- **Цепочка родства** на карточке человека — видно не только «кем
  приходится», но и сам путь: Марина → мама → бабушка → … → этот
  человек, каждое звено кликабельно.
- **Галерея и увеличение фото** — у человека может быть несколько
  фотографий, клик открывает полноэкранный просмотр с перелистыванием
  (стрелками с клавиатуры тоже).
- **Печать / PDF** — кнопка «Печать» на дереве рода даёт чистую версию
  для печати или сохранения в PDF через диалог браузера (тёмный фон
  автоматически меняется на белый, лишние элементы интерфейса прячутся).
- **Страница «Даты»** — дни рождения живых родственников и дни памяти
  ушедших, отсортированные по ближайшей дате от сегодняшнего дня.
  Учитываются только точные даты (день+месяц+год); если у человека
  указан только год — он не попадёт в расписание, но будет учтён в
  примечании «ещё у N человек нет точной даты».

## Автоматические подсказки по фамилиям и подсветка пробелов (новое)

- **Раздел «Фамилии»** теперь сам следит за деревом: как только там
  появляется фамилия без проверенной статьи, страница показывает по
  ней черновик — по типовым правилам русской ономастики (окончания
  «-ов/-ин/-ский» и т.д.), честно подписанный «автоматически, не
  проверено» (жёлтая рамка, файл `js/surname-rules.js`). Это не вызов
  ИИ и не факт — набор языковых закономерностей; Марина может поправить
  текст вручную в любой момент, отредактировав `js/content.js`.
- **Админка → Люди** теперь показывает, у кого не хватает ключевых
  сведений (дата рождения, место рождения, чем известен/род занятий,
  родство) — с счётчиком пробелов и переключателем «показывать только
  неполные». Отсутствие фото считается отдельно и не в счёт «пробелов»
  — фото это приятное дополнение, а не обязательное поле.
- Поле «Биография» на карточке переименовано в **«Чем известен(на) /
  жизненный путь»** — с подсказкой в форме, что туда писать (род
  занятий, за что запомнился, где и как жил).

## ⚠️ Важно про постоянство данных при деплое — прочитайте перед запуском

Файл `data/overlay.json` — это по сути маленькая база данных на диске.
**На многих бесплатных тарифах хостингов (в том числе Railway без
подключённого Volume) диск пересоздаётся при каждом передеплое** — то
есть добавленные Мариной люди и фото могут пропасть при следующем
обновлении кода. Это не теоретический риск, а реальное поведение таких
платформ — предупреждаю прямо, чтобы это не стало сюрпризом.

**Как сделать данные по-настоящему постоянными на Railway:**
1. В настройках сервиса откройте вкладку **Volumes** → **New Volume**.
2. Убедитесь, что Volume привязан **к тому же сервису**, где крутится
   `server.js` — если в проекте несколько сервисов, это частая ошибка.
3. Точка монтирования (Mount Path): любая, например `/data`.
4. Передеплойте сервис — и всё. **Переменную `DATA_DIR` вручную задавать
   не нужно**: сервер сам подхватывает путь через `RAILWAY_VOLUME_MOUNT_PATH`
   — эту переменную Railway выставляет автоматически, если Volume
   подключён к сервису правильно. Ручная `DATA_DIR` нужна только для
   нестандартных случаев (например, свой VPS без Railway).

**Если фото всё равно слетают после того, как Volume добавлен** —
откройте вкладку **Deployments → (последний деплой) → Logs** сразу
после запуска и найдите блок «Диагностика хранения данных» в самом
начале лога. Он прямо говорит, что не так — например, если строка
`RAILWAY_VOLUME_MOUNT_PATH` показывает «НЕТ», значит Volume физически
не подключён к этому сервису (несмотря на то, что где-то в проекте он
существует), и это самая частая причина проблемы.

Без Volume сайт полностью работает, просто данные негарантированно
постоянны между деплоями — это стоит явно проговорить с Мариной, чтобы
она не полагалась на сайт как на единственное место хранения важных
фотографий без резервной копии.

## FamilyIndex: расследование, ИИ (DeepSeek), заметки

Это большая доработка (по вашему ТЗ «развитие FamilyIndex»), добавляет:

- **Точки расследования** — переключатель «🔎 Показать точки
  расследования» на страницах «Дерево» и «Люди» подсвечивает маркерами
  `?` людей с пробелами (неизвестный отец/мать, братья-сёстры, супруг,
  дети, девичья фамилия, даты, места). На карточке человека — секция
  с этими пробелами и статусами (неизвестно / нужно исследовать /
  исследуется / есть гипотеза / найден кандидат / подтверждено /
  связи нет / закрыто вручную). Статус «закрыто вручную» или «связи
  нет» скрывает маркер насовсем.
- **Заметки с типами** — семейное воспоминание, со слов родственника,
  гипотеза, нужно проверить, обычная. Привязываются и к человеку, и к
  конкретной точке расследования.
- **Раздел «Расследование»** (`#/investigation`) — канбан с колонками
  Нужно проверить → Ищу → Потенциальные родственники → Подтверждено →
  Отклонено. Отклонённые кандидаты не удаляются (защита от повторных
  предложений). Совпадение оценивается только как «сильное / возможное
  / слабое» с объяснением причин — никаких процентов вероятности.
- **DeepSeek (ИИ)** — подключается на сервере переменной окружения
  `DEEPSEEK_API_KEY` (получить на platform.deepseek.com). Без ключа
  всё остальное продолжает работать, кнопки с 🤖 просто честно
  говорят, что ИИ не настроен, вместо того чтобы падать непонятно.

  **Важная техническая честность**: обычный API DeepSeek не умеет сам
  «ходить в интернет» — это подтверждено их официальной документацией
  (только function calling, где саму функцию обязано выполнять
  приложение). Поэтому кнопка «🤖 Искать» не ищет в интернете сама —
  она формирует умные поисковые запросы и объясняет/сравнивает то, что
  вы найдёте по ним и внесёте вручную через форму «Сохранить
  кандидата». Если захотите настоящий автопоиск — понадобится ещё один
  ключ (например, Serper.dev или Bing Search API) и доработка
  `SearchProvider` в `research-service.js`.

  Также используется актуальное имя модели `deepseek-v4-flash` —
  старое `deepseek-chat` официально отключено с 24 июля 2026.

## Что умеет сайт

- **Главная** — история семьи, карта мест, происхождение фамилий.
- **Дерево** — все люди по поколениям (римские цифры, I — самые
  дальние известные предки), с кнопкой печати/PDF и переключателем
  «🔎 Показать точки расследования» (маркеры `?` на карточках).
- **Расследование** — канбан потенциальных родственников, подробнее в
  разделе «FamilyIndex: расследование, ИИ» выше.
- **Схема** — радиальная диаграмма родства с зумом, панорамированием и
  мини-картой; выбор любого человека центром.
- **Хронология** — горизонтальная шкала времени всех известных дат.
- **Люди** — список с поиском и фильтром по линии (отец / мать / родня
  мужа).
- Карточка человека показывает **как он приходится Марине** и саму
  **цепочку родства** — считается автоматически по связям в дереве
  (`js/relations.js`), не вписывается руками. Там же — галерея фото с
  полноэкранным просмотром, точки расследования, типизированные
  заметки и кнопка «🤖 Создать досье».
- **Фамилии** — происхождение фамилий (общие сведения об ономастике, не
  архивные факты о конкретно вашей семье — указано на странице).
- **География** — деревни и город, где рождались члены семьи, включая
  официально упразднённые.
- **Админка** — добавление людей и **нескольких фотографий на
  человека** (сжимаются перед сохранением), быстрое добавление
  родственника одной кнопкой, и возможность убрать отдельную ошибочную
  связь (например, у Ларисы Ильиных в исходных данных указано три
  родителя одновременно — лишнюю связь можно снять через «✕» на её
  карточке).

## Деплой

**Railway** — загрузите проект (git или `railway up`), Railway найдёт
`package.json` и запустит `npm start`. Обязательно настройте Volume и
`DATA_DIR`, как описано выше, если данные должны переживать деплои.

**Локально** — `node server.js`, затем `http://localhost:3000`.

Netlify/Vercel как чисто статический хостинг **не подойдут** для этой
версии — им негде выполнять `server.js` и держать `data/overlay.json`.
Нужна платформа, которая запускает Node-процесс (Railway, Render,
свой VPS и т.п.).

## Структура проекта

```

css/style.css          дизайн-система «созвездие поколений»
data/seed.json          исходный снимок вашего дерева (не редактируется API)
data/overlay.json       правки Марины — редактируется сервером, тут живут данные
                        (люди, связи, точки расследования, заметки, кандидаты)
js/content.js           текст: происхождение фамилий, география
js/db.js                клиент API: запросы к серверу, кэш в памяти вкладки
js/relations.js          расчёт «кем приходится» и радиуса для схемы родства
js/gaps.js               определение точек расследования (пробелов) по дереву
js/relationship-suggestions.js  многофакторные подсказки по недостающим связям
                        (отчество + возраст + место + фамилия + семья, без ИИ)
js/quests.js              игровые задания: генерация из пробелов, уровни, streak, значки
js/surname-rules.js       автоматическая этимология фамилий по типовым правилам
js/history-ru.js          курируемый список значимых событий истории России и мира
js/places-geo.js          реальные координаты мест рода (для карты на Leaflet)
js/app.js                весь UI, маршрутизация, админка, канбан «Расследование»
server.js                статика + REST API + хранение на диске
ai-service.js            тонкая обёртка над DeepSeek API (AiService из ТЗ)
research-service.js      промпты и правила честности для каждой AI-функции
                        (ResearchService из ТЗ)
search-providers.js       SearchProvider-архитектура (GeneralWebSearch,
                        GenealogySearch, MilitarySearch, DeepSeekWebSearch)
```

## Навигация и UX (новое)

- **Меню свернуто с 11 пунктов до 6**: Главная, «Люди ▾» (Дерево/Схема/
  Список), «Время ▾» (Хронология/Даты), «Исследование ▾»
  (Расследование/Летопись/Фамилии), География, Админка.
- **Мобильное меню — гамбургер**, а не разворачивание всех пунктов
  сразу. Раньше шапка на телефоне занимала 243px и весь первый экран,
  теперь — 65px.
- При реорганизации нашёл и починил старый, ранее незаметный баг:
  общее CSS-правило сбрасывало `position: sticky` и `z-index` у шапки —
  из-за этого клики по новым выпадающим меню проваливались в контент
  под ними. Плюс похожая история с атрибутом `hidden` у окна поиска,
  которое CSS перебивал через `display: flex`.
- **Поиск по сайту** (иконка 🔍 в шапке) — ищет по людям и фамилиям
  одновременно.
- **Хлебные крошки** на карточке человека.
- **Канбан «Расследование»** теперь с явной подсказкой о прокрутке и
  затемнением края, когда колонки не помещаются на экране.
- **Публичный индикатор заполненности архива** на главной — виден
  всем посетителям, не только Марине в админке.
- **Leaflet теперь подключается лениво** — только на страницах, где
  реально есть карта (Главная, География), а не глобально на каждой
  странице сайта.

## Настоящая карта и обновлённая главная (новое)

- **Карта на Leaflet с настоящими координатами** вместо декоративной
  SVG-схемы — на «Географии» и новым блоком на главной. Тёмные тайлы
  CartoDB (бесплатно, без API-ключа). Координаты — реальные, из
  открытых источников: Кострома и Вохма — по Википедии, Согра —
  вычислена по известному расстоянию «13 км к северо-западу от
  Вохмы» оттуда же. Для исчезнувших деревень (Ершово, Мартьяновцы)
  координаты приблизительные и явно так подписаны в подсказке на
  карте — точное место физически утрачено. Для места рождения самой
  Марины («Филино») координаты намеренно оставлены неизвестными: в
  области несколько одноимённых деревень, гадать не стал.
- **⚠️ Не проверено визуально в этой сессии** — у меня не было
  доступа в интернет, чтобы увидеть, как карта реально отрисовывается
  в браузере. Ссылки на библиотеку и её хеши целостности перепроверены
  как подлинные через поиск, код написан по официально документированному
  паттерну — но первый визуальный тест стоит сделать сразу после
  деплоя, на страницах «Главная» и «География».
- Если карта всё же не загрузится (например, недоступен CDN) —
  теперь вместо молчаливого пустого прямоугольника показывается
  понятное сообщение с просьбой проверить соединение и обновить
  страницу.
- **Мозаика фото** на главной — живая сетка лиц рода по мере того, как
  добавляются фотографии.
- **Плитки быстрого доступа** к Летописи, Схеме, Расследованию,
  Хронологии.
- **Лента «Недавно в архиве»** — объединяет новых людей, заметки,
  найденных кандидатов и обновления летописи в одну хронологическую
  ленту с относительным временем.
- Блок «Сегодня вспомним» **больше не показывает произвольный фрагмент
  биографии** — раньше туда мог случайно попасть чувствительный факт
  (например, обстоятельства смерти), теперь показывается только род
  занятий; полная биография доступна на странице самого человека, куда
  переходят осознанно, а не натыкаются случайно на главной.

## Задания и геймификация (новое)

Вкладка **«🎯 Задания»** в админке — теперь первая, что видит Марина
после входа. Идея: превратить те же самые пробелы в данных (что и на
странице «Расследование») в понятные игровые задания одним человеком =
одна карточка, а не построчно по каждому полю:

- «Добавить фото: Скрябин Алексей Измайлович», «Заполнить карточку: ...»,
  «Найти родственников: ...», «Подтвердить историю фамилии: ...»
- **Тема дня** — набор заданий, который выделяется первым, меняется по
  дню года (сегодня фото, завтра истории жизни и т.д.), без сервера и
  без ИИ, детерминированно.
- **Очки, уровень, streak.** Уровни — от «Новичок архива» до «Мастер-
  генеалог», с прогресс-баром до следующего. Streak считает дни подряд
  с хотя бы одним выполненным заданием.
- **Задание засчитывается само**, как только реальное поле заполнено —
  отдельной кнопки «готово» нет специально: честнее и приятнее, когда
  система сама замечает, что вы сделали работу, а не когда просят
  отметить галочку.
- **Значки** — «10 фотографий», «Неделя подряд», «Скрябины заполнены»
  и другие, считаются от факта, не хранятся отдельно (кроме списка уже
  начисленных заданий и streak — это в `overlay.quest` на сервере).
- Список заданий, если их много, ограничен 12 штуками с кнопкой
  «Показать все», чтобы вкладка не превращалась в бесконечную простыню.

## Статус по ТЗ FamilyIndex

**Исправления после проверки на реальном сайте (ИИ подтверждён рабочим):**
- Подтверждение фамилии теперь реально сохраняет текст — раньше была
  только галочка без сохранения. Кнопка «✓ Подтвердить эту версию» в
  ответе ИИ и кнопка «✎ Редактировать» для ручной правки.
- Отклонённые подсказки по связям больше не предлагаются повторно —
  раньше кнопка «Отклонить» просто прятала строку в браузере, не
  сохраняя решение; теперь список отклонённых пар хранится на сервере.
- Прокрутка «Хронологии» больше не сбрасывается фоновым обновлением.
- Попутно найден и исправлен более серьёзный баг: после любого
  сохранения формы карточка иногда не обновлялась на экране, хотя
  сервер честно подтверждал сохранение — виновата более ранняя защита
  от стирания форм фоновым опросом, которая по ошибке блокировала и
  легитимную перерисовку после собственного сохранения. Плюс защита от
  гонки состояний между фоновым опросом и вашим же сохранением.

- **Летопись** (`#/chronicle`) — длинный связный AI-рассказ о роде от
  самых дальних известных предков до Марины, по главам, строго по
  фактам (жёсткий запрет на вымысел в промпте). Имена людей в тексте
  кликабельны — всплывающая карточка с фото, датами и степенью родства.
  Хранится на сервере, видна всем посетителям. Кнопка «Обновить
  летопись» — не автоматически при каждом добавлении человека (это
  стоило бы денег при каждом визите на сайт), а по требованию; если
  дерево пополнилось с момента последнего составления, наверху
  появляется заметное предупреждение об этом.
- **Подсказки по связям** переписаны на многофакторную оценку:
  раньше при совпадении по одному отчеству предлагались ВСЕ подходящие
  по имени и возрасту люди сразу (могло быть больше десятка ложных
  срабатываний на дерево из 75 человек). Теперь для каждого случая
  сравниваются несколько кандидатов сразу (возрастной разрыв, место
  рождения, фамилия, уже известный брак с матерью ребёнка), и
  предлагается только явный лидер — если однозначного лидера нет,
  подсказка не выводится вовсе, вместо гадания.
